# Тест-дизайн: лендинг bug-test.online

**Проект:** ручное тестирование лендинга bug-test.online
**Роль:** QA-инженер
**Дата:** 2026-08-26
**Статус документа:** готов к ревью

---

## 1. Введение

Документ фиксирует тест-дизайн полей формы обратной связи: классы эквивалентности (EP) и граничные значения (BVA). Основа — анализ требований (docs/01-requirements-analysis.md): правила полей взяты из реестра (раздел 5), неоднозначные случаи закрыты допущениями (раздел 9).

Идентификаторы классов используются дальше по цепочке трассировки: требование → класс эквивалентности → тест-кейс → баг-репорт.

Ожидаемые результаты: для незаполненных обязательных полей текст ошибки известен — «Обязательное поле» (FR-05). Для значений неверного формата точный текст ошибки в требованиях не задан (открытый вопрос, раздел 8 документа анализа), поэтому ожидаемый результат фиксируется как «ошибка формата» без конкретного текста до получения ответа аналитика.

## 2. Поле «Имя» (FLD-01)

### 2.1 Правило

По реестру (FLD-01): тип — обязательное, формат — буквы кириллицы, длина от 1 до 30 символов.

Принятые допущения (раздел 9 анализа): дополнительно разрешены буква «ё», а также пробел и дефис для составных имён («Анна Мария», «Анна-Мария»).

### 2.2 Классы эквивалентности

| ID | Тип | Класс | Пример | Ожидаемый результат |
|---|---|---|---|---|
| EP-01 | Валидный | Только буквы кириллицы, включая «ё», длина 1–30 | Анна, Ёлкин | Поле принято, отправка успешна |
| EP-02 | Валидный | Кириллица с пробелом внутри | Анна Мария | Поле принято |
| EP-03 | Валидный | Кириллица с дефисом внутри | Анна-Мария | Поле принято |
| EP-04 | Невалидный | Пустое поле | — | Ошибка «Обязательное поле» |
| EP-05 | Невалидный | Только пробелы | «   » | Ошибка «Обязательное поле»: значение фактически отсутствует |
| EP-06 | Невалидный | Латиница | Anna | Ошибка формата |
| EP-07 | Невалидный | Цифры | 12345 | Ошибка формата |
| EP-08 | Невалидный | Спецсимволы | @#$% | Ошибка формата |
| EP-09 | Невалидный | Эмодзи | 😀 | Ошибка формата |
| EP-10 | Невалидный | Смешанное значение: валидная кириллица + недопустимые символы | Анна123, Anna_Мария | Ошибка формата |
| EP-11 | Невалидный | Длина более 30 при валидном составе символов | 31 буква кириллицы | Ошибка превышения длины |

Примечания к классам:

- EP-05 выделяется отдельно от EP-04: поле «не пустое», но состоит из пробелов. Частая дыра в валидации.
- EP-10 ловит валидацию, которая проверяет только первый символ или наличие хотя бы одного допустимого символа вместо проверки всей строки.

### 2.3 Граничные значения

Границы берутся только по длине. Строки наполняются валидными символами (буквы кириллицы), чтобы проверялась именно длина, а не формат.

| ID | Кол-во символов | Граница | Наполнение | Ожидаемый результат |
|---|---|---|---|---|
| BV-01 | 0 | Ниже минимума | пусто | Ошибка «Обязательное поле» |
| BV-02 | 1 | Минимум | А | Поле принято |
| BV-03 | 2 | Минимум + 1 | Ан | Поле принято |
| BV-04 | 29 | Максимум − 1 | А × 29 | Поле принято |
| BV-05 | 30 | Максимум | А × 30 | Поле принято |
| BV-06 | 31 | Максимум + 1 | А × 31 | Ошибка превышения длины |

Примечание: если у поля установлен атрибут maxlength="30", браузер может физически не дать ввести 31-й символ с клавиатуры. Тогда BV-06 проверяется вставкой 31 символа из буфера обмена; если ограничение сработало и там — фиксируем поведение как наблюдение, а не дефект.

## 3. Поле «Фамилия» (FLD-02)

### 3.1 Правило

По реестру (FLD-02): тип — необязательное, формат — буквы кириллицы, длина 0–30 символов. Если поле заполнено — от 1 символа.

Принятые допущения (раздел 9 анализа): при заполнении разрешены «ё», пробел и дефис, как для поля «Имя».

### 3.2 Классы эквивалентности

| ID | Тип | Класс | Пример | Ожидаемый результат |

| EP-01 | Валидный | Пустое поле | — | Поле принято (необязательное) |
| EP-02 | Валидный | Кириллица 1–30, включая «ё» | Иванов, Ёлкин | Поле принято |
| EP-03 | Валидный | Кириллица с пробелом | Ван Дер | Поле принято |
| EP-04 | Валидный | Кириллица с дефисом | Салтыков-Щедрин | Поле принято |

| EP-06 | Невалидный | Латиница | Smith | Ошибка формата |
| EP-07 | Невалидный | Цифры / спецсимволы / эмодзи | 123, @#$ | Ошибка формата |

### 3.3 Граничные значения

| BV-01 | 0 | Минимум (пусто) | — | Поле принято |
| BV-02 | 1 | Минимум + 1 (первый символ) | А | Поле принято |
| BV-03 | 2 | Выше минимума | Ан | Поле принято |
| BV-04 | 29 | Максимум − 1 | А × 29 | Поле принято |
| BV-05 | 30 | Максимум | А × 30 | Поле принято |
| BV-06 | 31 | Максимум + 1 | А × 31 | Ошибка превышения длины |

## 4. Поле «Телефон» (FLD-03)

### 4.1 Правило

По реестру (FLD-03): тип — обязательное, формат — цифры, длина ровно 11 символов.

Принятые допущения (раздел 9 анализа): проверяем как 11 цифр без форматирования. Варианты с «+» в начале и с первой цифрой 7/8 — спорные, до уточнения аналитика. Маска из макета (19 символов с пробелами/скобками) не используется как эталон.

### 4.2 Классы эквивалентности

| ID | Тип | Класс | Пример | Ожидаемый результат |
|---|---|---|---|---|
| EP-01 | Валидный | 11 цифр | 79123456789 | Поле принято |
| EP-02 | Спорный | 11 цифр с «+» в начале | +79123456789 | До уточнения: ожидается ошибка формата |
| EP-03 | Спорный | 11 цифр, первая цифра 8 вместо 7 | 89123456789 | До уточнения: принимается как 11 цифр |
| EP-04 | Невалидный | Пустое поле | — | Ошибка «Обязательное поле» |
| EP-05 | Невалидный | Меньше 11 цифр | 7912345678 | Ошибка длины |
| EP-06 | Невалидный | Больше 11 цифр | 791234567890 | Ошибка длины |
| EP-07 | Невалидный | Буквы / спецсимволы / пробелы / дефисы | 79123abc, 791-234 | Ошибка формата |
| EP-08 | Невалидный | Смешанное: цифры + буквы | 7912345678a | Ошибка формата |

### 4.3 Граничные значения

Проверяется количество цифр. Наполнение — только цифры.

| ID | Кол-во цифр | Граница | Ожидаемый результат |
|---|---|---|---|
| BV-01 | 0 | Пусто | Ошибка «Обязательное поле» |
| BV-02 | 10 | Минимум − 1 | Ошибка длины |
| BV-03 | 11 | Ровно 11 | Поле принято |
| BV-04 | 12 | Минимум + 1 | Ошибка длины |

Примечание: если поле имеет маску, ввод 12-й цифры может блокироваться на UI. Тогда BV-04 проверяется вставкой.

## 5. Поле «Текст» (FLD-04)

### 5.1 Правило

По реестру (FLD-04): тип — обязательное, формат — буквы, цифры, спецсимволы, длина 1–300 символов.

Принятые допущения (раздел 9 анализа): конкретный перечень спецсимволов не задан; латиница и эмодзи — до уточнения, пока считаем допустимыми.
